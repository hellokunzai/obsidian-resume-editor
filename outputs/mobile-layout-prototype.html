一、核心：移动端单栏 + 切换已锁定，逐条确认
项规格说明 / 理由
移动端判定Platform.isMobile 手机 + 平板均走单栏。桌面端窄窗口不触发（避免拖窗时布局跳变）。
默认面板编辑页每次打开视图都重置为编辑页。
切换按钮方案 A · 单按钮 顶栏最左。标签为目标态：在编辑页显示「👁 预览」，在预览页显示「✏ 编辑」。i18n 新增 btn.showPreview / btn.showEditor。
切换状态持久化不持久化仅存于视图实例内存，关标签页即重置。
切回预览的刷新renderPreview() 重跑 必须。applyPreviewPageLines() 依赖 paper.scrollHeight，元素在 display:none 下测量为 0，A4 分页线会算错。
预览宽度等比缩放 A4 纸张固定 794px + transform: scale(可用宽/794)，transform-origin: top left；外层用负 margin 补偿缩放后的空白高度。与 PDF 导出像素级一致。
顶栏适配标题隐藏 + 按钮改图标 392px 宽下 5 个文字按钮必然换行挤掉内容区。导出 / AI 检查 / 保存改 29×29 图标按钮（带 aria-label），模板下拉压到 88px。
桌面端影响零 切换按钮在非移动端根本不创建（不是 CSS 藏起来）；单栏与 ↑↓ 样式全部挂 .re-mobile 前缀。
manifestisDesktopOnly: true → false 已核查 src/ 全量无 fs/path/os/electron/child_process；PDF 走 html2pdf（纯前端 canvas）、DOCX 走 docx（纯 TS）、落盘走 vault.adapter.writeBinary，移动端均可用。
二、附带修复：↑↓ 排序按钮你已选择本次一并做
项规格说明
根因HTML5 dragstart/dragover 触屏完全不触发这套事件，移动端现状是无法调整任何顺序。
影响范围（重要）4 处可拖拽列表 比我初评的 1 处多：① 模块 .re-module；② 经历条目 .re-entry-card（教育/工作/项目共用）；③ 基本信息字段 .re-basic-field-row；④ 证书作品 .re-entry-card。改动量修正为 约 90～110 行（抽一个公用 moveInArray() + buildMoveButtons() 复用）。
按钮位置插入各自 actions 区最前 模块 → .re-module-actions；条目 → .re-entry-actions。位于「显示/隐藏」「删除」左侧，视觉与现有 22×22 图标按钮完全一致。
拖拽手柄移动端隐藏 .re-mobile .re-drag-handle, .re-mobile .re-entry-drag { display:none }。桌面端不变。
边界态首项 ↑ / 末项 ↓ 禁用 加 disabled + .re-disabled（复用现有「基本信息不可删」的禁用样式）。
点击后行为换序 → 重渲染 → 存盘 renderModules() / renderEntries() → renderPreview() → scheduleSave()，与拖拽结束后的逻辑一致。
i18n新增 2 个 keybtn.moveUp / btn.moveDown（en + zh-cn）。
三、附带修复：PDF 移动端降 scale你已选择本次一并做
项规格说明
改动点src/export/pdf.ts html2canvas.scale 由固定 2 改为 Platform.isMobile ? 1.5 : 2。约 3 行。
代价移动端导出图像略软 1.5× 在手机屏与常规打印下肉眼几乎无差；换来内存占用下降约 44%（面积比 1.5²/2²），显著降低低端机 OOM 失败率。
失败兜底已有现有 try/catch + Notice(t("error.export")) 保留不动。
